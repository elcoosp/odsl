# ADR-003: Deterministic Lockfiles as the Migration Contract

- Status: Accepted
- Date: 2026-08-16

## Context

OSDL needs a reliable way to compute schema migrations without a human writing
each `ALTER` by hand. The risk is non-determinism: if the same schema can
produce different "current state" snapshots, auto-diffing becomes
untrustworthy and migrations drift from reality.

The codebase references "ADR-003" in comments about deterministic lockfiles, but
no ADR document previously existed. This record captures the decision.

## Decision

1. The `osdl.lock` file is a deterministic, canonical JSON projection of a
   compiled `Ast` (sorted models and fields, stable key order).
2. Two structurally-equal schemas always produce byte-for-byte identical
   lockfiles (REQ-NFR-DET-001).
3. Migrations are computed by diffing the *prior* lockfile (the recorded state)
   against the *target* lockfile (the desired state). The prior lockfile is the
   source of truth for rollback DDL (`down_sql` reconstructs inverse statements
   from it).
4. The lockfile format is part of the public contract. Breaking it requires a
   MAJOR version bump and a migration guide. A golden "load a v0.1 lockfile"
   test guards against accidental breakage.

## Consequences

- Migration plans are reproducible and reviewable (`osdl migrate preview`).
- Rollback is always possible from the recorded prior lockfile, removing the
  earlier data-loss risk where `DropModel`/`DropField`/`AlterField` down was
  `None` or a comment guard.
- Lockfile changes must be treated as API-breaking; CI includes a lockfile
  compatibility test.
